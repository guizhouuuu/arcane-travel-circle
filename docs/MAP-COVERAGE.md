# 地图覆盖与 NPC Map Locations 兼容说明

本文描述1.2.1的实现边界。下文普通地图坐标解析指大阵的任意位置传送；小阵网络使用已放置节点的真实场景和坐标，不要求从地图画面反推地块。世界地图是示意图，普通点击不能保证每个像素都对应唯一可站立地块。

## 1.1.0新增覆盖

- 大阵与小阵均支持邻接右键开地图，原有站阵手动开图也保留。
- 沙滩普通地面与北侧出口链通过真实资源离线回归；水下有明确可通行桥面或栈道时允许落脚，裸水仍拒绝。
- 原版采石场桥的图画范围(232,39,10,2)映射到实际修复桥片(92,24)内的桥面，左右点击仍有不同地块。实际四行桥面可走，中间栏杆不落脚；未修桥保持进度限制。
- 公会入口点击范围采用其完整9×9图标，候选出口来自真实AdventureGuild地图的Mountain(76,9)。
- 所有已放置传送阵显示地图标记；跨区域、没有精确地图投影或被视口裁掉的节点放入有名称的可滚动侧栏，仍能互传。不同位置过密的标记会错开并画连接线。
- 网络小阵可放农场外常驻室外地图，节点传送不受下文普通投影的场景白名单限制；仍需场景存在、非临时、可达且有安全落点。

## 正常玩法能够选择的地点

在农场传送阵上打开地图时，原版会根据玩家当前所在场景选择 `Valley` 地图。首版可解析以下原版室外场景：

| 室外场景 | 映射依据 | 额外条件 |
| --- | --- | --- |
| 农场 `Farm` | 当前农场实际地图尺寸与世界地图农场区域 | 正常可通行落点 |
| 鹈鹕镇 `Town` | 原版区域及位置矩形 | 正常可通行落点 |
| 煤矿森林 `Forest` | 原版区域及位置矩形 | 正常可通行落点 |
| 深山 `Mountain` | 原版区域及位置矩形 | 东侧桥梁及采石场受桥梁修复状态限制 |
| 海滩 `Beach` | 原版区域及位置矩形 | 未修桥时拒绝桥梁和东侧区域 |
| 巴士站 `BusStop` | 原版区域及位置矩形 | 安全落点另排除会被原版传送流程改写坐标的西侧位置 |
| 农场北方小路 `Backwoods` | 原版区域及位置矩形 | 正常可通行落点 |
| 铁路 `Railroad` | 原版区域及位置矩形 | 使用原版 `Game1.isLocationAccessible` 判断是否开放 |
| 秘密森林 `Woods` | 原版区域及位置矩形 | 至少有一名玩家实际进入过该场景，作为已通过入口障碍的保守证明 |
| 沙漠 `Desert` | 下文描述的显式近似修正 | 使用原版 `Game1.isLocationAccessible` 判断是否开放 |

表中“支持”指目标解析规则已实现，不代表已在游戏中逐地点实测。原版农场类型使用其当前实际地图尺寸。新增场景、修改原版场景布局的扩展 Mod、自定义农场及其他地图替换组合均没有全面兼容承诺。

## 坐标与候选选择

实现读取正在显示的 `MapPage`，保留它的纹理、标记、提示框和输入菜单。鼠标使用 UI 坐标；地图原点取自该页面当前的 `mapBounds.X/Y`。

本机 1.6.15 的 `mapBounds` 具有 UI 像素原点，但宽高尚未乘 `Game1.pixelZoom`。画布命中范围因此采用宽高乘像素放大倍数后的矩形。`MapAreaPosition.GetPixelArea()` 已经应用像素放大，反算地块时不会再重复放大。窗口尺寸或 UI 比例变化后，读取当前页面数据，不采用写死的屏幕点击矩形。

每个有效 `WorldPositions` 条目提供图像区域和实际地块区域。空 `TileArea` 使用场景地图第一层的实际大小，非空区域按场景边界裁剪。点击位置在图像矩形内的比例被反算到真实地块，采用与游戏正向映射对应的宽高分母。同一区域内不同的点击位置可产生不同的候选地块，随后在有限范围内寻找安全落点。

位置条目的 `Condition` 由游戏的 `GetWorldPositions()` 筛选。重叠时，面积较小的明确位置矩形优先于覆盖整个场景的大矩形；相同精度的候选仍指向不同场景或地块时，返回“位置不明确”，不会按数据顺序随便选一个。较小但无法解析的图标也不会被较大的场景矩形覆盖。

未获得地点信息、目标不受支持、没有可靠映射、目的地尚未开放或找不到安全落点时，玩家留在原地。地图空白也不会默认为农场。

## 沙漠的近似修正

实际原版 `Valley/Desert/Desert` 条目把沙漠、绿洲、骷髅洞穴和相关室内地点统一显示在世界地图的一个 `1×1` 像素标记上。这种数据无法恢复沙漠中的不同地块。

首版仅对与本机原版数据完全匹配的该条目启用集中修正：标记为 `(36,20,1,1)`、区域为 `(0,0,73,38)`、空地块区域且地点列表包含 `Desert` 时，使用整张沙漠绘图区域到实际沙漠地图的线性近似。不同点击会对应不同地块，但示意图中的建筑或道路不保证与实际位置精确重合。此修正不会传入绿洲、赌场或骷髅洞穴。映射 ID 带有 `full-region-approximation` 以便审核与排错。

如果其他 Mod 改变上述条目或区域，修正不会强行套用；仍按当前数据可提供的信息解析或拒绝。

## 建筑图标

当一个世界地图位置明确对应室内场景时，实现读取该场景的实际 `warps`。如果能确定唯一的受支持室外出口，则以真实出口为候选，寻找门外安全落点。重复指向同一室外地点、同一出口地块的记录会合并。

存在多个不同出口时拒绝歧义；出口只能到另一个室内空间、缺少出口或仅指向不支持场景时，不猜测门的位置，也不进入室内。矿洞楼层、赌场、火山楼层等不属于首版直接点选目标。固定点图标可以可靠定位已知的唯一室外门口，但不能用于反推整个室外场景。

## 解锁判断

- 沙漠、铁路采用本机游戏公开的 `Game1.isLocationAccessible(locationName)`，沿用游戏中的开放判断。
- 深山桥梁从 `X=92` 开始，相关候选使用原版 `Mountain.MakeMapModifications` 所用的 `Utility.doesMasterPlayerHaveMailReceivedButNotMailForTomorrow("ccCraftsRoom")`。该辅助方法兼容普通邮件与 `%&NL&%` 通知，并排除仍安排在明日的施工。
- 海滩桥梁在原版 `Beach.fixBridge` 中位于 `X=58..61`。`X>=58` 的候选要求 `Beach.bridgeFixed` 或 `beachBridgeFixed` 世界状态已成立，避免通过搜索落到桥另一侧。
- 秘密森林采用“已经实际访问过”的保守证明。刚清除入口木头但尚未走进去时，会先要求玩家正常进入一次。
- 安全落点搜索会对每个候选再次调用相同解锁判断，避免从一个未锁地块搜索到附近的未解锁区域。

## 姜岛与其他限制

农场上打开的 `Valley` 地图仅显示姜岛总览图标，其原版数据是 `LocationContext=Island` 的固定点。普通地图点击仍无法据此反推岛上具体地块。1.1.0支持点击侧栏中已放置在姜岛的真实小阵节点，按其保存坐标传送。

解析器能够读取原版 `GingerIsland` 详细区域中的明确室外映射，但正常的“农场阵上开地图”流程不会显示这张详细地图，首版因此不宣称可以通过该流程直接传送到岛上任意位置。如果其他环境显示这张地图，岛区候选仍要求玩家已经实际访问过对应场景。

山顶、女巫沼泽、火山顶及缺少可逆映射的固定室外标记不作为首版目标。夜市与其他临时节日替换场景、额外世界地图区域和扩展地图没有首版支持承诺。发生临时场景替换时还需由传送入口检查实际 `LocationRequest`，确保安全检查的地图与真正到达的地图相同。

## NPC Map Locations 3.5.2 的兼容依据

已读取本机 `Mods/NPCMapLocations/manifest.json`：版本为 `3.5.2`，唯一 ID 为 `Bouhm.NPCMapLocations`。同时使用实际 DLL 元数据确认：

- `NPCMapLocations.Framework.Menus.ModMapPage` 继承原版 `StardewValley.Menus.MapPage`。
- 该类覆盖悬停、头像与提示框绘制方法，没有覆盖 `receiveLeftClick`。
- 它使用继承的 `mapBounds`、`mapRegion` 和地图坐标。

本 Mod 使用 `is MapPage` 接受其派生页面，保留已有 `GameMenu` 和地图页面。传送代码不替换页面或贴图，不清除 NPC 标记，不对地图打 Harmony 补丁（仅法师小阵卡片购买与悬停各有一处补丁），不依赖 NPC Mod 的私有 API。仅在来源阵有效、人物仍在操作距离、没有子菜单且左键点击地图画布时处理并抑制该次点击；标签页、关闭按钮和配置子菜单保留原有操作。小阵的地面图形不加入NPC路径或碰撞系统。

相关上游实现可查阅 [NPC Map Locations 源码](https://github.com/Bouhm/stardew-valley-mods/tree/main/NPCMapLocations) 与 [ModMapPage](https://github.com/Bouhm/stardew-valley-mods/blob/main/NPCMapLocations/Framework/Menus/ModMapPage.cs)。其版本号与继承关系以本机实际文件核对结果为准。

## 已核对与尚未实测

已静态核对：本机 Stardew Valley `1.6.15.24356` 的 MapPage、MapArea、MapAreaPosition、MapRegion 的实际字段、方法和坐标计算；本机 `Data/WorldMap.xnb` 的两个区域及原版位置数据；海滩和深山的实际修桥代码；NPC Map Locations `3.5.2` DLL 的继承和覆盖方法；其公开上游地图页面实现。

这些检查通过只读程序集、文档及数据资产完成。没有为本说明启动、关闭或操控用户正在运行的游戏。NPC 标记与悬停提示同时显示、地图配置菜单、所有地点的实际到达行为、窗口/UI 比例变化、存档重进、购买扣款与建筑移动等游戏内验收仍需执行；静态兼容依据不能替代这些实测。

## 1.2.0：普通沙滩与艾利欧特小屋

实际世界地图同时存在无条件的Beach和BeachNightMarket矩形；只对原版Valley/BeachNightMarket及原始(186,137,57,31)特征排除替代层，避免正常Beach被误判为未知覆盖。活动夜市仍由传送协调器的地图替换检查拒绝。ElliottHouse的位置矩形扩展到其原版ElliottCabin图标提示范围，通过真实室外warp选择Beach入口，不传进屋内。普通沙滩其余区域继续按不同点击反算不同tile并搜索安全位置；不把整片沙滩集中送到小屋门口。

## 1.2.1：公会及采石场的远端初始化

点击映射本身保持原有公会出口、采石场桥连续投影和区域投影。安全检查先对远端Mountain应用原版MakeMapModifications，并按实际游玩天数预测原版入场时清除的滑坡/铁路状态，防止未访问场景的旧状态造成假封闭区域。早期封路、未修桥、水、岩石、树木和墙仍检查；没有扩大搜索半径或用固定入口替代区域点击。
